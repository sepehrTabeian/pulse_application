# CODING STANDARDS — MANDATORY (read before writing ANY code)

> Audience: every AI assistant and human contributor. These rules are a **lint**: a violation is a defect, not a style opinion.
> Each rule has an ID. When you deviate, you must stop and ask the Tech Lead; never deviate silently.
> Status words: **MUST / MUST NOT** = hard rule. **SHOULD** = default, deviation needs a written reason.

---

## 0. Workflow gates (process lint)

- **WF-01** Every task is analysed as **Context → Decision → Result**: what situation/constraint, what was chosen and why (options + edge cases), what was delivered and verified.
- **WF-02** MUST NOT start the next task until the Tech Lead explicitly approves the current one.
- **WF-03** A task is not done without tests; tests are not accepted without edge cases (see §10).
- **WF-04** At the end of every task, update `docs/PROGRESS.md`: what is done, what remains, open questions.
- **WF-05** Questions for the lead go at the END of the task report.
- **WF-06** Commits: Conventional Commits (`feat|fix|refactor|docs|test|chore|perf|ci(scope): subject`), one logical change per commit, imperative mood, no trailing period.
- **WF-07** `pulse_api` MUST NOT be modified.

## 1. Technology constraints

| Concern | Mandated | Forbidden |
|---|---|---|
| State management | `flutter_bloc` — Bloc/Cubit | Riverpod, Provider, GetX, raw `setState` for app state |
| DI | `get_it` | service locators other than get_it, global singletons, static mutable state |
| Debounce/throttle/stream ops | `rxdart` event transformers inside Bloc | `Timer`-based hand-rolled debounce in widgets |
| Code generation (models, logic, DI, state, routing) | **none** | `build_runner`, `freezed`, `json_serializable`, `injectable`, `auto_route`, any `*.g.dart` / `*.freezed.dart` |
| Localization codegen | `flutter gen-l10n` ONLY (official, ARB-driven) — the single allowed exception | any other generator |
| Numbers (money/qty/price) | `Decimal` (package `decimal`) | `double`/`num` for money, price, quantity |
| Equality | `equatable` (hand-written, not generated) or manual `==`/`hashCode` | |

- **TECH-01** `pubspec.yaml` MUST NOT contain `build_runner` or any generator in `dev_dependencies`. The ban covers **models, serialization, business logic, DI, state, routing**. (ADR-0001)
- **TECH-02** Only exception: localization via `flutter gen-l10n` (ARB files → `AppLocalizations`). It needs no `build_runner`; output is generated by Flutter's own tool and committed under `lib/core/l10n/generated/` (never hand-edited, excluded from the standards script). (ADR-0001, ADR-0002)

## 2. Clean Architecture

```
packages/
  pulse_design_system/        # independent module (own pubspec) — §8
lib/
  core/                       # cross-cutting: di, errors, network, utils, l10n, theme wiring
  features/<feature>/
    domain/                   # PURE DART. entities, repository interfaces, use cases, value objects
    data/                     # models (DTO), mappers, data sources, repository impls
    presentation/             # bloc/cubit, pages, widgets (feature-specific)
  app.dart  main.dart
```

- **ARCH-01** Dependency rule: `presentation → domain ← data`. Domain imports **nothing** from Flutter, `pulse_api`, `data`, or `presentation`.
- **ARCH-02** Only `data/` (and the composition root `lib/core/di/`, `main.dart`) may import `package:pulse_api`. One class (the API gateway/data source) wraps `FakeTradingApi`; the rest of the app sees interfaces.
- **ARCH-03** Presentation calls **use cases** where there is logic (submit, reconcile, load watchlist), or small **domain role interfaces** (e.g. `InstrumentSearcher`, `AccountReader`) for pass-through calls. It NEVER touches data classes, models or `pulse_api`. (ADR-0010, Q14)
- **ARCH-04** One use case = one business action, a callable class with a single public method.
- **ARCH-05** Package-style imports only (`package:pulse/...`), never `../` across layers.
- **ARCH-06** Files < 400 lines (hard cap 800), functions < 50 lines, nesting ≤ 4.

## 3. Entities vs Models (business separation)

- **MODEL-01** **Entity** (domain): immutable, business-meaningful, valid-by-construction types (e.g. `Instrument`, `PriceQuote`, `Order`, `Position`). No JSON knowledge. Uses `Decimal`, enums, value objects — never raw strings for business values.
- **MODEL-02** **Model** (data): mirrors the wire format (`InstrumentModel`, `OrderModel`…), hand-written `fromJson`/`toJson`, and a mapper `toEntity()` / `fromEntity()`.
- **MODEL-03** Entities and Models are different classes even if fields match today. UI MUST NOT see Models; domain MUST NOT see Models.
- **MODEL-04** All classes immutable: `final` fields, `const` constructors, `copyWith` hand-written where needed, unmodifiable collections.

### 3.1 Defensive parsing (server may send null / wrong type / missing keys)
- **PARSE-01** MUST NOT use `as T`, `!`, or `json['x'] as String` on external data. All access goes through a single hand-written tolerant reader (e.g. `JsonReader`) with typed getters: `string('k')`, `decimal('k')`, `integer('k')`, `boolean('k')`, `list('k')`, `map('k')`. Each returns `null` (or throws a typed parse exception for *required* fields) — never a `TypeError`.
- **PARSE-02** Accept type drift where unambiguous (number sent instead of decimal string, `"true"` vs `true`, int vs string `seq`) — normalize, don't crash.
- **PARSE-03** Each field is classified **required** or **optional** per business meaning. Missing/invalid *required* field ⇒ `ParsingException` (a client exception) carrying field name + raw type. Optional ⇒ safe default/`null`.
- **PARSE-04** Unknown JSON keys / unknown message `type` values are ignored (forward-compatible). Unknown enum values map to an `unknown` member, never throw.
- **PARSE-05** Stream messages: one bad message MUST NOT kill the stream — drop it, count it, continue.
- **PARSE-06** `jsonDecode` result may be any type; check `is Map<String, Object?>` before use; wrap decoding in `on FormatException`.
- **PARSE-07** Every Model has tests for: null field, wrong type, missing key, extra key, empty body, non-object root.

## 4. SOLID (enforced)

- **SOLID-S** One reason to change per class. A Bloc orchestrates state; it does not parse, validate, format, or call the API.
- **SOLID-O** Extend via new classes/strategies (e.g. new order type = new validator/strategy), not by editing `switch` ladders in many places.
- **SOLID-L** Implementations honour interface contracts (same exceptions, same nullability, same ordering guarantees). Fakes in tests too.
- **SOLID-I** **Segregated interfaces — small, role-based.** Do not create `TradingRepository` with 12 methods. Prefer `WatchlistReader`, `WatchlistWriter`, `PriceStreamSource`, `OrderPlacer`, `OrderLookup`, `InstrumentSearcher`, `AccountReader`, `CandleReader`. A client depends only on the methods it uses. One concrete class may implement several interfaces; consumers see only one.
- **SOLID-D** Depend on abstractions. High-level policy (use cases, blocs) never constructs concrete collaborators; they are injected via constructor (§6).

## 5. SSOT & SOC

- **SSOT-01** Each piece of state has exactly one owner:
  - Prices → one `PriceStreamService`/repository stream; blocs *subscribe*, never keep a second copy.
  - Watchlist → `confirmed` list owned by the watchlist repository/bloc; optimistic view derived from it.
  - Order lifecycle → the order bloc's state machine (+ persisted attempt record).
  - Instrument rules (tick/lot/tradable) → instrument repository only.
- **SSOT-02** No duplicated derived values stored in two places; compute from the source (e.g. change %, estimated cost).
- **SSOT-03** Constants/magic numbers live in one place (`core/constants` or the owning layer). Money formatting in one formatter.
- **SOC-01** UI widgets: render state + dispatch events. No business logic, no parsing, no try/catch of data errors.
- **SOC-02** Navigation, localization, theming, DI wiring are separate concerns from features.
- **SOC-03** Formatting (`Decimal` → text) lives in presentation formatters, using locale from l10n; domain stays locale-free.

## 6. Dependency Injection (get_it)

- **DI-01** Composition root: `core/di/injection.dart` — the ONLY place that calls `GetIt.instance.register*`.
- **DI-02** Register **interfaces**, not concretions: `registerLazySingleton<OrderPlacer>(() => OrderRepositoryImpl(...))`.
- **DI-03** Lifetimes: `FakeTradingApi` = ONE singleton for the whole app (README). Repositories/services = lazy singletons. Blocs/Cubits = `registerFactory` (provided via `BlocProvider`), unless a bloc is explicitly app-scoped.
- **DI-04** Classes receive dependencies through **constructors**. `GetIt.I<T>()` MUST NOT be called inside domain/data/bloc classes or widgets' `build` (only in composition root / `BlocProvider.create`).
- **DI-05** Tests build their own `GetIt` instance or construct objects directly with fakes; call `reset()` in `tearDown`.
- **DI-06** `dispose`/`close` registered for anything holding resources (`FakeTradingApi.dispose()`, stream subscriptions, Blocs).

## 7. State management (Bloc/Cubit)

- **BLOC-01** Use **Bloc** when events need transformers (debounce, droppable, sequential) or ordering semantics (order submission, search, stream events). Use **Cubit** for simple synchronous/linear state.
- **BLOC-02** State is a `sealed` hierarchy or a single immutable class with a status enum; widgets use exhaustive `switch`. Every async state has: `initial/loading/success/failure` (+ `empty` where lists apply). Failure carries an `AppException`, not a string.
- **BLOC-03** **Debounce = RxDart + Bloc.** Implement as reusable `EventTransformer<E>` helpers in `core/bloc/` built on `rxdart` (`debounceTime` + `switchMap`/`flatMap`), applied via `on<Event>(handler, transformer: …)`. No `Timer`, no debounce in widgets. Search input uses it.
- **BLOC-04** Concurrency policy is explicit for every handler (`sequential`, `droppable`, `restartable`). Order submit is `droppable`/guarded (see §9).
- **BLOC-05** Blocs MUST NOT hold `BuildContext`, MUST NOT call `Navigator`/show snackbars. UI reacts to state via `BlocListener`/`BlocBuilder`.
- **BLOC-06** Cancel subscriptions and timers in `close()`. Use `emit.forEach`/`emit.onEach` for streams to get automatic cancellation.
- **BLOC-07** Row-level rebuilds: use `BlocSelector`/per-row `buildWhen` so one price tick rebuilds one row.
- **BLOC-08** Never `emit` after `close`; guard with `isClosed` in async callbacks outside `emit` helpers.

## 8. Design system, theme, localization

- **DS-01** `packages/pulse_design_system` is an **independent Dart/Flutter package** with its own `pubspec.yaml`, tests and `README`. It depends on NOTHING from the app (no domain, no bloc, no get_it, no l10n of the app).
- **DS-02** It exports: design tokens (colors, spacing, radii, typography, motion, elevation), `ThemeData` factories (light/dark), and presentational widgets (price cell, change badge, status chip, primary button with `pending` state, empty/error/loading views, banners).
- **DS-03** Widgets take plain values and callbacks; all text is passed in by the caller (already localized). No hardcoded user-facing strings in the design system.
- **DS-04** No hardcoded colors, sizes, `TextStyle`s, or `Duration`s in feature code; use tokens/theme extensions.
- **DS-05** Price direction is NEVER color-only: arrow/icon + sign + semantics label.
- **DS-06** Tokens, theme and widgets all live in this ONE package. Initial tokens follow **Material 3** (`ColorScheme.fromSeed`, M3 type scale, M3 shapes). Tokens are exposed through our own token classes / `ThemeExtension`s (e.g. semantic `priceUp`, `priceDown`, `stale`), never raw `Colors.*`, so a designer's tokens can replace the values later without touching feature code. (ADR-0004)
- **THEME-01** Light + dark themes, via `ThemeData`/`ThemeExtension`; app follows system by default.
- **L10N-01** Zero user-facing string literals in widgets/blocs. All via generated `AppLocalizations` (`flutter gen-l10n`). **Current version: Persian (`fa`, RTL) is the default and only shipped locale; English (`en`) is added later** — so ARB structure, plurals, and layouts must already support multiple locales and both directions (`EdgeInsetsDirectional`, `AlignmentDirectional`, no hardcoded left/right). (ADR-0002)
- **L10N-02** Errors map to localized messages through an injected resolver (§11), never `exception.toString()` or server `message` verbatim.
- **L10N-03** Numbers/currency/dates formatted via locale-aware formatters; Decimal never converted through `double`.

## 9. Order safety (RED LINES)

> **RED LINE — certainty:** NEVER assume or guess the outcome of an order request. A state is shown as FILLED/WORKING/REJECTED only after the server confirmed it. Until then it is `submitting` or `unknown`. No optimistic updates for orders, positions, cash.

- **ORD-01** After the user taps submit, the order bloc moves to `submitting` **synchronously**. UI is in **pending** state: submit button disabled (with progress), all inputs (side, qty, type, limit price), close/back/swipe-dismiss of the ticket guarded, and no other order action reachable.
- **ORD-02** Single-flight is enforced **in the Bloc** (droppable/guard + state check), not only by disabling the button. A second `Submit` event while not in an editable state is ignored.
- **ORD-03** `clientOrderId` (UUID v4 via injected `IdGenerator`) is created once per attempt and **persisted before** the network call (injected `PendingOrderStore`). It's reused for every retry/reconciliation of that attempt. Changed params ⇒ new attempt ⇒ only after the previous attempt is resolved.
- **ORD-04** `TimeoutException` (or any unconfirmed result) ⇒ state `unknown/resolving`, inputs stay locked, UI says "checking order status". Resolve by re-sending the **same payload with the same `clientOrderId`** (idempotent) and/or `getOrder`. Bounded retry with exponential backoff + jitter. Never surface a timeout as "failed".
- **ORD-05** `503` ⇒ retry same id. Definitive rejections (4xx/422) ⇒ `rejected` with localized, specific reason. `409 IDEMPOTENCY_CONFLICT` ⇒ treated as a bug path: surface + log, do NOT auto-retry with a new id.
- **ORD-06** Terminal states only: `filled | working | rejected`. `unknown` is NOT terminal; if retries are exhausted, remain `unknown` with a manual "check status" action (same id) — still never guess.
- **ORD-07** On app start, reconcile persisted non-terminal attempts before allowing a new order for that symbol.
- **ORD-08** After `filled`, refresh account (cash/positions) from server; do not compute locally.
- **ORD-09** Pre-submit validation (client): symbol tradable, side, quantity > 0 and multiple of `lotSize`, limit price present for LIMIT and multiple of `tickSize`, estimated cost shown (BUY: ask / SELL: bid / LIMIT: limit price). Validation failure ⇒ no request is sent.

## 10. Validation & input

- **VAL-01** All user input is validated before use through domain-level validators (pure Dart, injected, unit-tested), returning typed validation results/exceptions — not ad-hoc `if`s in widgets.
- **VAL-02** Text input: sanitize/trim, restrict allowed characters (`[0-9.]`), reject multiple separators, limit length and scale (decimal places ≤ step scale), handle locale decimal separators explicitly.
- **VAL-03** Validation messages are localized and field-specific. Validate on change (debounced where costly) and again on submit.
- **VAL-04** Watchlist: ≤ 20 symbols, no duplicates (client-side before request); search query trimmed, min length rule defined, debounced.
- **VAL-05** Never trust server data either (see §3.1).

## 11. Error handling (exceptions, interface-based, DIP)

All errors are **`Exception`s**. No `Either`/`Result`-as-error carriers, no returning error strings.

```
abstract interface class AppException implements Exception {
  String get code;        // stable machine code
  Object? get cause;      // original error/stack for logs
  bool get isRetryable;
}
├── ServerException (abstract)      — errors that came from the backend
│     ├── InvalidRequestException      (400 INVALID_*)
│     ├── NotFoundException            (404)
│     ├── IdempotencyConflictException (409)
│     ├── BusinessRuleException        (422: INSUFFICIENT_FUNDS, TRADING_HALTED, WATCHLIST_FULL…)
│     ├── ServiceUnavailableException  (503, retryable)
│     └── UnknownServerException       (unmapped status/code)
└── ClientException (abstract)      — errors produced on the device
      ├── ValidationException        (input rules)
      ├── ParsingException           (bad/missing/mis-typed payload)
      ├── RequestTimeoutException    (outcome UNKNOWN)
      ├── StreamDisconnectedException
      ├── StorageException           (local persistence)
      └── UnexpectedException        (wrapped unknown Object, last resort)
```

- **ERR-01** `ApiException` / `TimeoutException` / `ConnectionLostException` / `FormatException` / `TypeError`-class issues from `pulse_api` or parsing are converted **once**, in `data/`, by an injected `ExceptionMapper` interface (`AppException map(Object error, StackTrace st)`). Nothing above `data/` references `pulse_api` exception types.
- **ERR-02** Domain/presentation depend on the `AppException` **interface** (DIP). They never match on `ApiException` or on message strings; they match on exception types/`code`.
- **ERR-03** `catch` clauses name types (`on ServerException catch (e)`). Bare `catch (e)` only at the outermost boundary of a Bloc handler/`runZonedGuarded` to wrap into `UnexpectedException`, with logging. Never catch `Error` to hide programming bugs. Never swallow silently.
- **ERR-04** Exceptions for control flow of *expected business outcomes* are fine here (project rule); exceptions carry enough typed data (symbol, limits) for the UI.
- **ERR-05** UI messages come from an injected `ErrorMessageResolver` interface (`String resolve(AppException, AppLocalizations)`), localized, user-friendly, with a retry affordance when `isRetryable`.
- **ERR-06** Logging via an injected `AppLogger` interface (no `print`, no `debugPrint` in committed code). Never log secrets/PII.
- **ERR-07** Read operations retry only `isRetryable` (503) with backoff+jitter, bounded; retry policy is an injected, testable class (`RetryPolicy`) — not copy-pasted loops.

## 12. Streams (summary — details in skill `stream-resilience`)

- **STR-01** One connection owner; dedupe per-symbol by `seq`; coalesce before UI; reconnect with backoff+jitter; staleness via heartbeat/silence timeout; close on background; swap stream on watchlist change; no leaks (`openConnectionCount`).
- **STR-02** Time is injected (`Clock`/`Stopwatch` abstraction or `fake_async`) so staleness/backoff are testable.

## 13. Testing (blocking)

- **TEST-01** No task is complete without tests. Tests without edge cases are rejected.
- **TEST-02** Write the failing test first (RED), then implement (GREEN), then refactor.
- **TEST-03** Layer tests: domain (pure unit), data (models/mappers/exception mapper/repositories with fakes), bloc (`bloc_test`), widget (key states). Coverage target ≥ 80% on domain + data + bloc.
- **TEST-04** Hand-written fakes over mocks for gateways; deterministic via `FakeTradingApi(seed:)`, `ChaosConfig.instant`, `fake_async`. Never real `Future.delayed` in tests.
- **TEST-05** Mandatory edge-case catalogue (cover what applies to the task):
  - **Numbers:** 0, negative, `0.0001` lot, very large qty, trailing zeros, leading/trailing `.`, locale separators, rounding at tick boundary.
  - **Parsing:** null / wrong type / missing / extra / empty / non-object.
  - **Network:** 503 once/N times, timeout, ghost timeout (executed but timed out), disconnect mid-stream, retry exhaustion.
  - **Concurrency:** double tap, submit while resolving, rapid watchlist edits, out-of-order & duplicate ticks, event after `close()`.
  - **Lifecycle:** app background/foreground, kill during pending order, hot restart.
  - **Business:** halted instrument, insufficient funds/position, watchlist full/duplicate, unknown symbol, empty watchlist, empty search.
- **TEST-06** Test names describe behavior: `returns X when Y`. AAA structure.

## 14. Code-level rules

- **CODE-01** Immutability: `final`, `const`, no mutation of passed-in collections; return `List.unmodifiable`.
- **CODE-02** Null safety: avoid `!`; avoid `late` unless guaranteed; prefer pattern matching/early returns.
- **CODE-03** `dart format` (80 cols), trailing commas; `dart analyze` clean (zero warnings) before declaring done.
- **CODE-04** Naming: `snake_case` files, `PascalCase` types, `camelCase` members; booleans read as claims (`isStale`, `hasPendingOrder`); no abbreviations.
- **CODE-05** No `print`, no commented-out code, no TODO without owner and ticket in `PROGRESS.md`.
- **CODE-06** `await` or `unawaited()` every Future; check `context.mounted` after awaits in widgets.
- **CODE-07** Accessibility: semantics labels on interactive/price widgets, ≥ 48dp touch targets, direction not by color alone.
- **CODE-08** Comments explain *why*, not *what*. Public APIs of domain interfaces have doc comments stating exceptions thrown.

## 16. Automated enforcement

- **ENF-01** `analysis_options.yaml` with strict lints (`strict-casts`, `strict-inference`, `strict-raw-types`, `avoid_print`, `prefer_const_constructors`, `always_use_package_imports`, `unawaited_futures`, `avoid_dynamic_calls`, …) — zero warnings.
- **ENF-02** `tool/check_standards.sh [root]` (wrapper around the Dart implementation in `tool/standards/checker.dart`; Dart instead of grep so comments/strings are stripped correctly and it is portable). Output `file:line RULE-ID message`; exit 0 clean / 1 violations / 2 usage error. A line may opt out with `// standards-allow: RULE-ID <written reason>` (missing reason = `ALLOW-01`). Detects: `double` on money/price/qty names, `as ` casts and `!` on JSON access, `print(`/`debugPrint(`, `build_runner`/generator packages in `pubspec.yaml`, `GetIt` use outside the composition root, `package:pulse_api` imports outside `data/`, `package:flutter` in `domain/`, hardcoded `Color(`/`Colors.` in features, string literals in widgets (heuristic), `*.g.dart`/`*.freezed.dart` files (except the l10n output directory).
- **ENF-03** The script itself is tested (`tool/test/`): fixture files for each rule with positive and negative cases and edge cases — violations inside comments, inside string literals, `import … as alias` (must not match `as` cast rule), identifiers merely containing the word (`doubleTap`, `printer`), generated l10n directory exclusion, CRLF line endings, unicode/space in paths, empty directory, no `lib/`, huge file, binary files. Exit codes asserted (0 clean / 1 violations) and output format asserted (`file:line RULE-ID message`). (ADR-0006)
